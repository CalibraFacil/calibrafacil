## Status do Método

Cada método de calibração possui um dos cinco status a seguir:

| Status | Editável | Disponível para calibrações | Descrição |
| :--- | :--- | :--- | :--- |
| **DRAFT** (Rascunho) | Sim | Não | Método em construção. Pode ser livremente editado. |
| **PENDING_APPROVAL** (Em aprovação) | Não | Não | Método enviado para revisão. Edição bloqueada. |
| **TECHNICAL_REVIEWED** (Revisão técnica) | Não | Não | Revisado tecnicamente e aguardando aprovação da qualidade. |
| **PUBLISHED** (Publicado) | Não | Sim | Método aprovado e disponível para uso em calibrações. |
| **ARCHIVED** (Arquivado) | Não | Não | Versão anterior, substituída por uma nova publicação. |

## Fluxo de Status

```
DRAFT → PENDING_APPROVAL → TECHNICAL_REVIEWED → PUBLISHED → ARCHIVED
  ↑            │                   │
  └────────────┴─────────────── (retornar com motivo)
                   │
                   └── (nova versão) → DRAFT (v2)
```

### Criação

Todo método começa no status **DRAFT** (versão 1). Nesse estado, todos os aspectos do método podem ser editados:
- Campos de entrada
- Fórmulas
- Critérios de aceitação
- Componentes de incerteza Tipo B
- Nome, descrição e tipo de ativo

### Solicitação de aprovação

Quando o método está pronto para uso, o responsável técnico clica em **Solicitar aprovação**. A solicitação:

1. Altera o status para **PENDING_APPROVAL**
2. **Bloqueia a edição** — o método não pode mais ser modificado
3. Envia o método para revisão técnica

### Revisão técnica

Um **Admin** realiza a revisão técnica. Ao aprovar:

1. O status passa para **TECHNICAL_REVIEWED**
2. O método fica aguardando aprovação da qualidade

### Aprovação da qualidade (publicação)

Um **Owner** realiza a aprovação da qualidade. A publicação:

1. Altera o status para **PUBLISHED**
2. Torna o método disponível para novas calibrações
3. Se existir uma versão publicada anterior, ela é automaticamente **arquivada**

<Aside type="note">
  Por conformidade e separação de responsabilidades, a revisão técnica e a aprovação da qualidade devem ser realizadas por usuários diferentes.
</Aside>

<Aside type="caution">
  A publicação é uma ação irreversível. Revise cuidadosamente o método na pré-visualização antes de solicitar aprovação. Para corrigir um método publicado, será necessário criar uma nova versão.
</Aside>

### Retorno a rascunho

Se houver ajustes necessários durante a aprovação, um **Admin** ou **Owner** pode retornar o método para **DRAFT**. Essa ação:

- Reabre a edição do método
- Requer **motivo obrigatório**
- Fica registrada na trilha de auditoria

### Versionamento

Para modificar um método já publicado:

1. O sistema cria um **novo rascunho** (versão N+1) como cópia do método publicado
2. O responsável edita o rascunho conforme necessário
3. Ao publicar o novo rascunho, a versão anterior é automaticamente **arquivada**

**Exemplo:**
- v1 (PUBLISHED) → Técnico precisa adicionar um campo
- v2 (DRAFT) é criada como cópia de v1
- v2 é editada e publicada → v2 (PUBLISHED), v1 (ARCHIVED)

### Arquivamento

Métodos arquivados:

- **Não aparecem** na lista de métodos disponíveis para novas calibrações
- **Permanecem vinculados** a calibrações já realizadas com aquela versão
- São acessíveis no histórico de versões do método

<Aside type="note">
  Calibrações existentes não são afetadas pelo arquivamento. Um certificado emitido com a versão 1 continuará referenciando a versão 1 do método, mesmo após a publicação da versão 2.
</Aside>

## Tipo de Ativo

Cada método pode ser associado a um **tipo de ativo** (categoria de equipamento). Exemplos:

- Termômetro Digital
- Balança Analítica
- Micrômetro
- Manômetro

A associação com o tipo de ativo permite:
- Filtrar métodos disponíveis ao iniciar uma calibração
- Sugerir automaticamente o método adequado para o instrumento recebido

## Trilha de Auditoria

O sistema registra automaticamente:

| Evento | Informações registradas |
| :--- | :--- |
| Criação | Usuário, data/hora, versão |
| Modificação | Usuário, data/hora, campos alterados |
| Solicitação de aprovação | Usuário, data/hora |
| Revisão técnica | Usuário, data/hora |
| Aprovação da qualidade | Usuário, data/hora, versão publicada |
| Retorno a rascunho | Usuário, data/hora, **motivo** |
| Arquivamento | Data/hora, motivo (nova versão ou manual) |

Esse registro atende aos requisitos de rastreabilidade da **ISO/IEC 17025:2017, Cláusula 8.4** (Controle de registros) e **Cláusula 7.11** (Controle de dados e gestão de informações).

## Boas Práticas

1. **Use nomes descritivos** — inclua o tipo de instrumento e a grandeza no nome do método (ex: "Calibração de Termômetro Digital - Temperatura")
2. **Documente a descrição** — inclua o procedimento de referência, faixa de medição e condições ambientais esperadas
3. **Teste antes de publicar** — use a pré-visualização para simular uma calibração completa com dados reais
4. **Mantenha o histórico** — ao criar uma nova versão, documente na descrição o motivo da alteração
5. **Revise os critérios** — garanta que as tolerâncias e limites estejam alinhados com as normas ou requisitos do cliente
