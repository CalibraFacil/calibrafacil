## Fluxo de Aprovação

Quando o técnico submete a OS para revisão, o responsável técnico (admin ou owner) recebe uma notificação e pode revisar todos os dados.

<Aside type="caution">
  **Separação de responsabilidades:** O técnico que executou a calibração **não pode** aprovar a própria OS. Isso garante conformidade com a **ISO/IEC 17025:2017** sobre imparcialidade e controle de resultados.
</Aside>

### Tela de Revisão

A página de detalhes da OS em status **EM REVISÃO** exibe:

- Informações do cliente e do instrumento
- Padrões de referência utilizados (snapshot)
- Dados de medição preenchidos pelo técnico
- Resultados de todas as fórmulas calculadas
- Status de cada critério de aceitação (aprovado/reprovado)
- Configuração do método (quantidade de campos, fórmulas e critérios)

### Aprovar

<Steps>

1. Revise todos os dados e resultados
2. Clique em **Aprovar**
3. Confirme a aprovação no diálogo
4. O status muda para **GERANDO PDF**
5. O certificado é gerado automaticamente em segundo plano
6. Após a geração, o status muda para **APROVADO**

</Steps>

### Rejeitar

<Steps>

1. Identifique o problema nos dados ou resultados
2. Clique em **Rejeitar**
3. Informe o **motivo da rejeição** (obrigatório)
4. O status retorna para **EM EXECUÇÃO**
5. O técnico é notificado e pode ver o motivo da rejeição
6. O técnico corrige os dados e submete novamente

</Steps>

<Aside type="note">
  A rejeição não descarta os dados — o técnico pode corrigir apenas o necessário e resubmeter. O motivo da rejeição fica visível na página da OS para referência.
</Aside>

## Geração do Certificado PDF

Após a aprovação, o sistema gera automaticamente o certificado de calibração em PDF:

1. A OS entra no status **GERANDO PDF**
2. Um processo em segundo plano (Cloudflare Worker) renderiza o certificado HTML
3. O HTML é convertido em PDF via Puppeteer
4. O PDF é armazenado no Cloudflare R2
5. A OS passa para o status **APROVADO**
6. O cliente recebe uma notificação de **CERTIFICATE_READY**

O certificado inclui:
- Identificação do laboratório e acreditação
- Dados do cliente e do instrumento
- Condições ambientais
- Resultados da calibração com incerteza expandida
- Critérios de aceitação e parecer (aprovado/reprovado)
- Rastreabilidade dos padrões utilizados

## Assinatura Digital ICP-Brasil

Certificados aprovados podem ser assinados digitalmente com certificado **ICP-Brasil A1** (padrão PKCS#12), conforme **NIT-DICLA-083**.

### Pré-requisitos

1. Certificado A1 (arquivo `.p12`) importado em **Configurações → Certificados**
2. Certificado dentro do prazo de validade
3. Usuário com permissão de assinatura (admin ou owner)

### Processo de Assinatura

Na página da OS aprovada, clique em **Assinar Certificado**. O sistema:

1. Aplica a assinatura digital ao PDF usando o certificado A1
2. Registra os metadados: assinante, CPF/CNPJ, serial do certificado, hash SHA-256 do PDF, data/hora
3. Habilita LTV (Long Term Validation) quando possível

<Aside type="tip">
  Configure a assinatura visual (imagem da assinatura manuscrita) em **Configurações → Assinatura** para que ela apareça no PDF assinado.
</Aside>

## Verificação Pública de Certificados

Cada certificado recebe um **token de verificação** único (UUID). Este token permite que clientes e auditores verifiquem a autenticidade do certificado sem necessidade de login:

- O certificado impresso contém um QR code ou link de verificação
- O link direciona para uma página pública com os dados do certificado
- A verificação confirma: emissão pelo laboratório, data, status (válido/retificado) e metadados da assinatura digital

## Download do Certificado

O PDF do certificado pode ser baixado por:
- **Equipe do laboratório:** Na página de detalhes da OS aprovada
- **Cliente (portal):** Na seção de certificados do [Portal do Cliente](/portal)
